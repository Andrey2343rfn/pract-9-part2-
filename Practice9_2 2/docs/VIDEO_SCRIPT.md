# Сценарій демонстраційного відео 5–7 хвилин

## 0:00–0:35. Вступ

«Вітаю. Це практична робота 9.2 з дисципліни “Технології IoT та SMART-технології”. Я виконав перший варіант, Smart Factory Monitoring System. Мета полягає в організації обробки показників промислових датчиків на Edge та аналізу в Cloud за допомогою Docker».

Показати структуру папок у VS Code.

## 0:35–1:25. Архітектура

«Симулятор формує шість показників обладнання. Через брокер MQTT дані надходять до Edge Processor. Він перевіряє допустимі межі, формує повідомлення про несправності та зберігає дані. Cloud Connector приймає записи, зберігає їх в InfluxDB та надає API для вебпанелі».

Показати `docker-compose.yml`, `edge/config.json`, схему архітектури.

## 1:25–2:10. Запуск Docker

Ввести:

```bash
docker compose up --build -d
docker compose ps
```

«Зараз працюють шість контейнерів. Сервіси підключені до двох внутрішніх Docker-мереж».

## 2:10–3:00. Сенсори та Edge

Ввести:

```bash
docker compose logs --tail=15 sensor-simulator
docker compose logs --tail=20 edge-processor
```

«Симулятор генерує температуру, вібрацію, струм, оберти, шум і тиск. Edge Processor аналізує дані та реагує на перевищення порогів. Наприклад, при високій температурі виконується команда охолодження».

## 3:00–3:50. Cloud та Dashboard

Відкрити `http://localhost:8080`. Показати шість карток, графік, журнал аномалій.

«Хмарна частина накопичує часові ряди, обчислює статистику та передає її у вебінтерфейс. Дані оновлюються автоматично кожні три секунди».

Натиснути «Зупинити лінію» або «Увімкнути охолодження», показати виконану дію на панелі та у логах Edge.

## 3:50–5:05. Тест автономної роботи

Ввести:

```bash
docker compose stop cloud-connector
docker compose logs --tail=12 edge-processor
docker compose exec edge-processor python -c "import sqlite3; c=sqlite3.connect('/app/data/edge.db'); print('Pending:', c.execute('SELECT COUNT(*) FROM pending').fetchone()[0])"
```

«Cloud Connector зупинено, але Edge продовжує аналізувати показники. Записи зберігаються в локальній черзі SQLite та чекають відновлення зв'язку».

Ввести:

```bash
docker compose start cloud-connector
docker compose logs --tail=15 cloud-connector
docker compose exec edge-processor python -c "import sqlite3; c=sqlite3.connect('/app/data/edge.db'); print('Pending:', c.execute('SELECT COUNT(*) FROM pending').fetchone()[0])"
```

«Після відновлення Cloud непідтверджені записи надсилаються повторно та видаляються з локальної черги після підтвердження. Повторні записи контролюються за унікальним event_id».

## 5:05–6:00. Висновок

«На локальному рівні рішення щодо несправностей приймаються без звернення до Cloud. Хмарна частина відповідає за довготривале зберігання й аналітику. Система підтримує збереження показників при відсутності Cloud, відновлення синхронізації та віддалені команди».

Показати `http://localhost:8080/api/summary`, PDF-звіт та результати тестів.

## Примітки до запису

- На macOS запис екрана: Command + Shift + 5.
- Голосовий коментар українською мовою.
- Статус `Up` у `docker compose ps` та реальні логи записати саме на своєму Mac.
- У PDF демонстраційні результати локальних функціональних тестів не замінюють Docker-демонстрацію.
